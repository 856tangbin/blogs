# 个人博客写作与分类规范

本文档是博客写作、分类和发布的长期约定。当前阶段只建立规范和工具，不改动已有文章；已有文章在单独审计和确认后迁移。

## 内容定位

- 主线是科研技术笔记，包括生物信息学、统计与因果推断、论文写作和软件工具。
- 同时保留科研生活内容，包括学习方法、科研随笔、读书笔记和成长复盘。
- 文章以中文为主；专业术语、软件名和缩写保留英文规范写法，例如 `MCMC`、`PyMC`、`Docker`、`IVW`、`LDSC`。

## 两级分类

分类回答“文章属于哪一栏”，统一使用一个一级分类和一个二级分类。

| 一级分类 | 二级分类 |
| --- | --- |
| 生物信息学 | 测序与数据提取、基因组分析、遗传率与遗传相关 |
| 统计与因果推断 | 回归与模型、贝叶斯与 MCMC、孟德尔随机化 |
| 论文写作 | 结构与章节、学术表达 |
| 软件与效率 | 环境与部署、编程与工具 |
| 科研生活 | 学习方法、科研随笔、读书笔记、成长与职业 |

分类路径维护在 [`blog-taxonomy.yml`](blog-taxonomy.yml) 中。不要在 front matter 中增加第三级分类，也不要用文章标题作为分类。

## Front matter 约定

每篇文章使用 Chirpy 支持的字段，不添加 `draft` 等自定义状态字段。

```yaml
---
title: 文章标题
description: 用 50–120 个中文字符概括文章解决的问题、核心结论和适用读者。
author: tangb
date: 2026-09-21 09:00:00 +0800
categories: [统计与因果推断, 回归与模型]
tags: [线性回归, 加权最小二乘]
pin: false
math: true
mermaid: false
---
```

- `title`、`description`、`author`、`date`、`categories`、`tags`、`pin` 为必填字段。
- `description` 写成不依赖正文的一句话摘要，不使用多行文本。
- `author` 默认使用 `tangb`。其他作者必须先加入 `_data/authors.yml`。
- `date` 使用北京时间，并与 `_posts` 文件名日期一致；发布时间确定后不再随文件修改时间变化。
- `categories` 必须使用上面的两级路径。
- `tags` 每篇 2–6 个，只能从 `blog-taxonomy.yml` 的白名单中选择；使用 ASCII 逗号，不允许中文逗号，不能重复，也不能与当前二级分类相同。
- `pin` 默认 `false`。只有系列入口或全站导航文章可以置顶，全站最多 2 篇。
- `math` 和 `mermaid` 只在正文确实使用时设为 `true`。

## 文件、URL 与图片

- 新文章命名为 `YYYY-MM-DD-中文语义标题.md`，例如 `2026-09-21-孟德尔随机化入门.md`。
- 文件名只使用中文、ASCII 字母数字和连字符；不要使用空格、括号或全角标点。
- 文件名去掉 `.md` 后作为 URL slug。已有文章保持原文件名和 URL，避免外链失效；新文章直接遵守新规则。
- 每篇文章使用独立图片目录：`assets/images/<文章文件名去掉.md>/`。
- 图片使用相对路径引用，例如 `../assets/images/2026-09-21-孟德尔随机化入门/01-研究设计.png`。
- 图片文件名不使用空格，不重复建立同主题的第二个目录。

## 草稿与发布

- 未完成文章存放在 `_drafts/中文语义标题.md`，草稿文件名不含日期。
- 草稿不参与线上构建；草稿使用正文内容表达状态，不使用 `draft` 标签。
- 发布时将草稿移入 `_posts/YYYY-MM-DD-中文语义标题.md`，补全发布日期、图片目录和 front matter，再通过校验。
- 后续迁移阶段将以下文章移入 `_drafts`：

  - `马尔客服蒙特卡洛法(案例补充1).md`
  - `2025-05-01-pyMC基本用法.md`

## 写作与协作流程

开始写作前先明确以下信息：

- 主题和文章要回答的核心问题
- 目标读者和技术深度
- 已有材料、草稿和需要核实的来源
- 期望篇幅、语言和发布方式
- 是否需要公式、代码、表格或图片
- 文章是正式发布还是继续放在草稿目录

我给出的第一版建议必须包含标题、slug、`description`、分类路径和标签；确认后再写入 Markdown 文件。技术文章按“问题 → 核心结论 → 原理或过程 → 例子或证据 → 边界与局限 → 参考资料”组织。个人随笔允许更自由的叙述，但必须有清楚的主旨、具体细节和结尾。

写作边界：

- 不凭空补造事实、数据、引用或实验结果。
- 来源不足时保留“待核实”标记，明确区分原始观点和编辑补充。
- 默认直接修改本地文件，不自动提交或推送。
- 发布前必须通过 front matter、分类、标签、日期、图片和代码块检查。

## 发布前检查清单

- 标题和 `description` 能独立说明文章价值。
- 一级、二级分类均来自 taxonomy，且顺序正确。
- 标签数量、拼写和白名单位置正确。
- 文件名日期与 front matter 日期一致。
- 公式、代码围栏和 Mermaid 开关匹配。
- 所有本地图片路径存在，且位于文章自己的图片目录。
- `pin: true` 的数量没有超过全站上限。
- 参考资料和不确定性说明完整。

## 校验命令

使用只读校验器检查文章，不修改文件：

```powershell
python tools/validate_blog.py --audit
python tools/validate_blog.py --strict
python tools/validate_blog.py --strict _drafts/示例草稿.md
```

`--audit` 用于查看已有文章的迁移差距，始终以成功状态退出；`--strict` 用于新文章和待发布文章，发现错误时返回失败状态。
